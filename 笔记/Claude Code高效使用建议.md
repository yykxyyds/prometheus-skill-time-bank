# 用 Claude Code 开发本项目的高效建议

## 一、把 CLAUDE.md 喂饱，每个阶段更新一次

CLAUDE.md 是 Claude Code 读取的最高优先级上下文。建议：

- **设计阶段**：把数据库表结构、ER 图要点写进去
- **编码阶段**：把模块间的依赖关系、API 接口约定、技术选型写进去
- 当前已包含：项目概述、硬性要求、进度、交付物 — 起步够了
- 每次对话不需要重复解释背景

---

## 二、善用 `笔记/` 目录存"上下文快照"

多模块 Spring Boot 项目信息量大，不可能每次都塞给 Claude。建议写以下笔记：

| 笔记 | 用途 |
|------|------|
| 数据库表结构定义 | 给 Claude 看表结构，生成 CRUD 代码时不需要重复描述 |
| API 接口清单 | 模块间通信的 REST API 定义，生成 Feign 客户端时用 |
| 技术决策记录 | 为什么选这个技术、踩过什么坑，避免反复踩 |
| 当前进度/待办 | 每次开始新对话时快速同步上下文 |

> 不需要每篇都很长，关键信息写清楚就行。

---

## 三、分阶段、分模块对话

Claude Code 有上下文限制，一次聊完所有模块会稀释注意力。推荐方式：

| 对话 | 内容 |
|------|------|
| 对话1 | 搭父 POM + common 模块 + 数据库表 SQL |
| 对话2 | 实现用户注册登录模块（user-service） |
| 对话3 | 实现技能货架模块（skill-service） |
| ... | 依次完成各模块 |

每个对话只聚焦 1-2 个模块。对话开始时先 Read `笔记/` 下的上下文快照 + CLAUDE.md，Claude 就能快速进入状态。

---

## 四、让 Claude 自检验证（自检再交付）

写完代码后让 Claude 自己验证，不要写完就交差：

- 写完 API → 启动服务 → curl 测试 → 截图结果
- 写完 SQL → 实际跑一下看建表是否成功
- 每次改动后跑诊断脚本或检查实际输出，确认无误才说完成

工具链参考（见 CLAUDE.md 通用技能备忘录）：
- Playwright 截图
- Edge Headless 轻量截图
- Spring Cloud 微服务启动流程

## 五、加分项按优先级做

| 优先级 | 加分项 | 工作量和说明 |
|--------|--------|-------------|
| ★★★ | **Docker 部署**（必选） | `Dockerfile` + `docker-compose.yml`，这个必须先做 |
| ★★★ | **Redis 缓存** | 缓存热门技能列表，代码量小，效果明显 |
| ★★★ | **Swagger 接口管理** | 引入 springdoc-openapi，加几个注解即可 |
| ★★☆ | **幂等设计** | 订单支付接口加唯一请求号防重 |
| ★☆☆ | **消息队列** | 有余力再做，学习成本较高 |
| ★☆☆ | **CI/CD** | 有余力再做 |

---

## 六、小技巧

1. **生成代码前让 Claude 先读现有的表结构和代码**，避免生成不一致的代码
2. **用 `项目代码/` 子目录区分模块**：`user-service/`、`order-service/` 等，Claude 读写文件路径清晰
3. **复杂决策先使用 Plan Mode**：Claude Code 内置的 `EnterPlanMode` 会在动手前让你确认方案，避免写了一半发现方向错了
4. **不确定就问，不隐藏困惑**：有多个理解就列出来给用户确认，不要自己猜
5. **改代码像外科手术**：只改必须改的，不顺手"优化"旁边无关的代码
